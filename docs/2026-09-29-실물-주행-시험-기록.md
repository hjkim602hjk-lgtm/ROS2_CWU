# 2026-09-29 실물 주행 시험 기록

Nucleo-F446RE 모터·엔코더와 `encoder_odom`을 실물 로봇으로 처음 맞춰 본 날의 기록입니다.
결론부터: **엔코더 오도메트리는 직진에서 맞지만, 모터 출발 순간의 전기 잡음으로 Nucleo의 USB 시리얼(ST-Link)이 깨지거나 멈춥니다.** 제자리 회전 오도메트리는 아직 검증되지 않았습니다.

## 구성

- 전원: 배터리에서 선을 따로 빼 USB-C로 Pi에 공급. 모터 전원은 같은 배터리에서 MDD10A로 들어가며, 로봇에서 따로 끌 수 없음.
- Pi ↔ Nucleo: USB(`/dev/ttyACM0`, ST-Link V2.1 `0483:374b`), 115200 baud.
- 펌웨어: 팀 원본(커밋 `44f761e`, `changwon_robot_2026-09-29.zip`)에 안전 수정을 더한 판. 현재 파일은
  `firmware/nucleo/legacy/changwon_robot_stm_20260929.ino.txt`. 한 글자 명령 `f b l r s z 1 2`, 출력 `ENC,<left>,<right>` 100 ms마다, 고정 PWM 100.

포트를 열 때 맨 앞 줄이 잘리거나 쌓인 줄이 몰려 들어오는 것은 잡음이 아니라 버퍼 문제라 무시합니다.

### 1~5의 근본 해결 후보

- **A. 배선 보강**: Nucleo GND ↔ MDD10A GND 굵은 선 직결, 모터선 쌍마다 꼬기, 신호선과 분리. 부품 없이 가능, 효과는 시험해 봐야 앎.
- **B. ST-Link 우회 (추천)**: F446 하드웨어 UART ↔ Pi GPIO UART 직결(TX·RX·GND, 3.3 V). 3~5는 모두 ST-Link USB가 멈추는 현상이고, 09-30 회전은 2/2로 출발 직후 멈춰 시험 자체가 안 됨. 대회 중 멈추면 USB를 다시 꽂을 수 없으므로 가장 약한 고리를 빼는 쪽이 확실함. 펌웨어 시리얼 포트 변경과 Pi UART 설정 필요.
- 세라믹 콘덴서(모터 단자)는 현재 없습니다.

**결정 (2026-09-30): B로 갑니다.** 배선은 Nucleo A0(PA0, UART4 TX) → Pi GPIO15/RXD(10번), Nucleo A1(PA1, UART4 RX) ← Pi GPIO14/TXD(8번), GND ↔ GND(6번).
USART1(D8)·USART6(PC7=D9)은 모터 핀과 겹쳐 제외했습니다. A2~A5는 PSD용으로 남습니다.
펌웨어 빌드 설정(`SERIAL_UART_INSTANCE=4`)과 ROS 기본 포트(`/dev/ttyAMA0`)는 바꿨습니다. 새 펌웨어 업로드·Pi UART 설정(`disable-bt`, 콘솔 제거)·실물 확인은 아직 안 했습니다. 세부는 README의 "Nucleo ↔ Pi 통신" 절.

`firmware/nucleo/src/`가 속도 PI 제어 펌웨어(`CFG`/`ACK`/`VEL`, 가속 제한 포함)로 바뀌었고 `motor_bridge.py`, `motor_safety.py`, `motor.yaml`이 추가됐습니다. 튜닝 값이 모두 `-1`이라 아직 로봇을 움직일 수 없습니다. 새 펌웨어는 `ENC,<ms>,<L>,<R>,<session>`을 보내므로 **올리기 전에 `encoder.yaml`의 `left_field`/`right_field`를 1/2로 바꿔야 합니다.**

## UART 전환 진행 상태 (2026-09-30 밤 기준)

ST-Link USB 끊김(위 3~5) 때문에 Nucleo UART4 ↔ Pi GPIO UART 직결로 바꾸는 중입니다.

| 단계 | 상태 |
|---|---|
| 핀 선정: Nucleo A0(PA0, UART4 TX) → Pi GPIO15/RXD 10번, A1(PA1, RX) ← GPIO14/TXD 8번, GND ↔ 6번 | **완료.** STM32duino 보드 정의로 확인. D3~D10(모터·엔코더)과 안 겹침, A2~A5는 PSD용으로 남음 |
| 펌웨어 | **완료(레포).** `firmware/nucleo/platformio.ini`에 `SERIAL_UART_INSTANCE=4`, `PIN_SERIAL_RX=PA1`, `PIN_SERIAL_TX=PA0`. 코드 수정 없이 `Serial`이 UART4가 됨. legacy·codex 펌웨어 둘 다 빌드 성공, map에 `Serial4` 확인 |
| ROS 기본 포트 | **완료.** `/dev/ttyACM0` → `/dev/ttyAMA0` (encoder/motor yaml, 두 노드, 런치 3곳, `tools/raw_enc_log.py`, README). colcon build 통과, pytest cwu_base 23 · cwu_nav 10 · cwu_slam 12 통과 |
| Pi UART 설정 | **이미 되어 있었음(바꾼 것 없음).** `config.txt`에 `enable_uart=1`·`dtoverlay=disable-bt`, `cmdline.txt`에 시리얼 콘솔 없음, `serial0 → ttyAMA0`(PL011), `ubuntu`는 `dialout`. `hciuart`는 enabled지만 BT 핀 조건 불충족으로 부팅 시 건너뜀, `ttyAMA0` 점유 프로세스 없음 |
| 새 펌웨어를 Pi에 복사 | **완료.** `~/firmware_uart4_legacy.bin` (sha256 `86161535…b9a88f`, legacy 펌웨어 + UART4) |
| 배선 | **안 함** (사용자) |
| 업로드 | **안 함.** 2026-09-30 시점 Nucleo가 Pi USB에 안 꽂혀 있었음(`ttyACM0` 없음), `ttyAMA0` 2초 읽기 0바이트 |
| 통신 확인 | **안 함** |

**다음 순서**
1. 바퀴 띄우기 → 배선(A0→10번, A1←8번, GND↔6번).
2. Nucleo USB를 Pi에 꽂고 사용자 터미널에서 업로드:
   `ssh -t rpi 'sudo mount /dev/sda /mnt && sudo cp ~/firmware_uart4_legacy.bin /mnt/ && sync; sudo umount /mnt'`
   업로드 후에는 ST-Link USB(`ttyACM0`)로 데이터가 안 나옵니다.
3. `/dev/ttyAMA0` 읽기만으로 `ENC` 10 Hz 확인 → 바퀴 띄운 f/l/b/r → 바닥 한 바퀴 재시험(09-30에 2/2 실패한 시험).
4. 이후 위 "다음 할 일" 5번(360° 회전으로 `wheel_separation` 보정), 6번(codex 초안 검토) 계속.

**같이 정리된 결정**
- PSD는 4개: 정면 그리퍼 1개(파지를 시작하는 유일한 PSD) + 좌·우·뒤 각 1개(주변 근접 감지, 용도 미정). README·`CLAUDE.md`·PSD 설계·대회 계획·노션 반영.
- 노션 "배선 · 전원 설계"의 옛 핀표(모터 PB4~PB7, 엔코더 PA0/PA1·PA6/PA7)는 실제 펌웨어와 다름. 경고와 실제 핀을 적어 둠. 실제 로봇 배선이 펌웨어(D3~D10)와 같은지 사용자 확인 필요.

## 연결 검사·Nucleo 무응답 (2026-10-02) — 다음에 여기서 시작

업로드 전에 Blink로 Nucleo ↔ Pi 연결을 확인하려다 F446이 응답하지 않는 것을 발견했습니다.

**한 조치**
| 조치 | 결과 |
|---|---|
| 연결 검사용 Blink 펌웨어 작성: `firmware/blink_check/` (`pio run -d firmware/blink_check`) | 빌드 성공. LD2 1 Hz 깜빡임, `BLINK,n`을 UART4(`ttyAMA0`)와 ST-Link VCP(`ttyACM0`) 둘 다로 출력, 받은 바이트 echo(`ECHO_UART4,x`/`ECHO_VCP,x`), 모터 핀 D6~D9 LOW 고정. Pi `~/firmware_blink.bin` (sha256 `e095dbc1…4c7b64`) |
| sudo 없는 업로드 경로 확인 | ST-Link USB 노드·`/dev/sda`가 `rw-rw-rw-`라 가능. ① `st-flash --reset write ~/firmware_blink.bin 0x08000000` ② `apt download mtools` → `dpkg -x`로 받은 `/tmp/mt/usr/bin/mcopy -i /dev/sda` (마운트 불필요, `/tmp`라 재부팅 시 다시 받기) |
| `st-flash` 업로드(일반, `--connect-under-reset`, `--freq=100k`) | 모두 `Can not connect to target`, `NRST is not connected` 경고 |
| `st-info --probe` | ST-Link V2J39S27는 잡힘, 대상 `chipid 0x0000` — F446 무응답 |
| Nucleo 드라이브 확인 | `FAIL.TXT`: "The interface firmware FAILED to reset/halt the target MCU" (USB 재연결 후에도 다시 생김) |
| 포트 읽기 2 s | `ttyACM0`·`ttyAMA0` 둘 다 0바이트 — 기존 legacy 펌웨어도 안 돌고 있음 |
| 보드 상태(사용자 확인) | LD3(전원) 켜짐, CN2 점퍼 2개·JP6 꽂힘, LD1 초록 고정, LD2 꺼짐 |
| USB 재연결 → 2분 감시 | 재인식 정상, 계속 `chipid 0x0000` |
| A0/A1 선 제거 후 재시도 | 같음 (RESET 핀 오배선 아님) |
| RESET(B2) 누르며 감시 | 첫 감시는 스크립트 인자 오류로 무효, 고친 감시는 `no target`. 그동안 버튼을 눌렀는지는 확인 못 함 |

**판단:** Pi·USB·ST-Link는 정상이고 F446 칩이 SWD에 응답하지 않습니다. 멀티미터 측정은 못 해서 3V3/NRST 전압은 미확인입니다. 칩 손상이 가장 유력합니다(09-29 모터 잡음·Pi 저전압과의 관련은 추정). 여분 Nucleo로 교체하기로 했습니다.

**발생한 문제:** 보드 교체 도중 Pi가 핑·SSH 모두 응답하지 않게 됨. 원인 미확인 — 새 Nucleo를 꽂을 때 저전압으로 재부팅됐을 가능성. 교체 감시 스크립트는 SSH 끊김(종료 코드 255)으로 출력 없이 끝남 — 끊기기 전까지 새 보드는 감지되지 않았고, Blink도 올라가지 않음.

**다음 순서**
1. Pi 전원·부팅 확인 → SSH 복구. `ttyACM0`가 root 0600이면 재부팅.
2. 새 Nucleo: D3~D10 선을 옮기고 A0/A1은 아직 빼 둔 채 USB를 Pi에 연결, 바퀴 띄움.
3. Pi에서 `st-info --probe`로 chipid 확인 → `st-flash --reset write ~/firmware_blink.bin 0x08000000`.
4. LD2 깜빡임 + `ttyACM0`의 `BLINK` 확인 → A0/A1 배선 → `ttyAMA0`에서 `BLINK`·echo 확인.
5. 통과하면 `~/firmware_uart4_legacy.bin`을 올리고 위 "UART 전환 진행 상태" 3번부터 계속.
6. 고장 보드는 따로 보관하고 표시. 멀티미터가 생기면 CN6 3V3/RESET 전압 측정.

### 구성
- 실행: `slam.launch.py drive:=true cmd_vel_topic:=cmd_vel_safe` + `cwu_nav nav2.launch.py drive:=true`
  (모든 주행 명령이 collision monitor를 거침). 복귀: `ros2 run cwu_nav go_home` (map 원점 = SLAM 시작 자세).

  방향 ±40° 탐색). 멀리 간 지점에서 SLAM과 2~3 cm 일치해 측정법 검증됨.
