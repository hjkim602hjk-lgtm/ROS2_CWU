# 대회 규정 대응 분석과 실행 계획

**작성일:** 2026-10-08  
**상태:** Codex 설계 초안 — Claude 검토·실물 검증 전  
**설계 의도:** 규정 위반 없이 두 미션을 완주하도록, 공통 주행·파지의 실물 신뢰성을 먼저 확보하고 미지 경기장 대응을 연결한다.

## 1. 판단과 근거

현재 가장 먼저 해결할 문제는 새 인식 알고리즘이 아니라 **실물에서 끊기지 않는 구동, 실제 확보·유지, 외부 개입 없는 임무 연결**이다. SLAM·Nav2·색상 검출은 이미 있으므로 재사용한다.

분석 기준은 [저장소 규정](../../competition_rules.md), [개발 원칙](../../../Agent.md), [현재 상태](../../../README.md), 기존 미션·PSD 설계와 구동 기록이다. 아래 조항 번호는 저장소 규정 문서의 번호다. 이 문서는 원본 규정(안)의 요약이므로 최종 확정 규정 확인은 별도 선행 과제이며, 이번 작업에서 주최 측 최종 규정을 확인한 것은 아니다.

대응의 기본 방향:

1. 규정이 공개한 경기장 크기·목표물 초기 중앙 위치는 활용한다. 미공개 장애물 배치·배정 출발점·목표물 현재 위치는 센서로 확인한다.
2. 공개 전에 코드·보정값·미션 프로그램을 확정한다. 경기 중 갱신하는 지도·경로·상태는 온보드 관측의 결과로만 생성한다.
3. 미션1은 중앙 우선 탐색 후 확보·복귀, 미션2는 확보·유지·탈락 회피를 우선한다.
4. 적극 탈취·공격적 밀기는 기본 완주가 재현된 뒤 검토한다. 공통 장치가 두 미션 모두에서 동작해야 한다.

**통로 검토:** 보수적으로 `실제 주행 외곽 폭 + 2 × 횡방향 여유 < 400 mm`가 필요하다. 여유는 위치 오차·추종 오차·기구 공차로 실측한다. 직선 통과만으로 회전까지 보장되지 않으므로 교차로 진입과 그리퍼 확장도 따로 시험한다. 안전 설정 때문에 통로가 막히면 여유를 근거 없이 줄이지 말고 속도·제동거리·기구 폭을 재검토한다.

**네트워크 검토:** `ROS_LOCALHOST_ONLY`는 ROS 통신 범위에 대한 설정이며 무선 모듈 차단 자체를 대체하지 않는다. 실행은 SSH 종료·무선 차단에 종속되지 않는 온보드 서비스/프로세스로 준비한다. 구체적 차단 시점·실행 명령 형식은 심판 절차와 사전에 맞춘다.

## 3. 현재 구현과 실제 부족한 부분

| 영역 | 확인한 상태 | 이번 계획에서 필요한 작업 |
|---|---|---|
| `cwu_slam` | SLAM·G4·TF·가상 검증 경로 있음 | 장착·실주행 지도 품질·Pi 부하 확인 |
| `cwu_base`·Nucleo | 모터 브리지·PI·watchdog 초안과 검사 있음 | UART4 업로드·Pi UART 설정·모터 노이즈 조건에서 실물 정지 검증 |
| `cwu_nav` | Nav2·Collision Monitor·목표물 방향 서보 있음 | Nav2/서보 명령 선택, 코너 제한, 미션 명령 연결 |
| `cwu_perception` | 컬러 `/target/bearing` 검출, 현재 작업 중인 변경 존재 | 실물 카메라·조명·장착 pitch·근접 화면 이탈 검증 |
| PSD·그리퍼 | 설계만 있고 제어 미구현 | 센서 모델·전압·거리 보정·구동기·유지 피드백 확정 후 구현 |
| 미션 제어 | 상태머신 설계만 있음 | 자동 탐색·접근·파지·복귀/유지·실패 전이 구현 |
| 경기장 좌표계 | SLAM 원점과 실제 중앙은 다름 | 벽 관측 기반 정합·신뢰도 판단 구현 |

`autonomy.launch.py`는 현재 `drive:=true`와 카메라/서보 동시 실행을 거부한다. 이는 첫 실물 주행 시험을 제한한 것이므로, 이미 전체 자율 임무가 연결됐다고 볼 수 없다. 안전 명령 선택과 파지 정지 연동을 검증한 뒤 경기용 조합을 허용해야 한다.

기존 문서의 과거 가상 검사 성공은 실물 합격 증거로 사용하지 않는다. 현재 작업 중인 인식 코드는 이번 문서 작업에서 수정하지 않았다.

## 4. 미션1 전략 — 확보하고 돌아오는 데 집중

### 정상 흐름

`시작 잠금 → 센서/구동 확인 → 시작 자세 기록 → 경기장 추정·탐색 → 목표물 정렬 → PSD 접근 → 정지·파지·유지 확인 → 시작점 복귀 → 도착 판정`

1. SLAM 좌표계가 준비되면 출발 자세를 기록한다. SLAM 재초기화·큰 좌표 보정 시 복귀 기준이 유효한지 확인한다. 절대 출발 격자를 사람이 입력하는 방식에 의존하지 않는다.
2. 경기장 벽을 충분히 관측해 중앙이 추정되면 중앙 방향을 탐색 우선순위로 쓴다. 모르는 장애물 영역을 통행 가능하다고 단정하지 않는다.
3. 중앙 추정이 어렵거나 경로가 막히면 관측된 자유공간에서 도달 가능한 미탐색 경계를 순차 방문한다. 이미 실패한 경로를 무한 반복하지 않는다. 점대칭은 참고 정보이며 반대편 공간의 안전을 확정하는 근거로 쓰지 않는다.
4. 목표물이 보이면 Nav2 이동을 취소하고 정지한 뒤 서보 제어로 전환한다. 카메라는 방향만 제공하며, 정렬됐을 때만 저속 전진한다. 화면에서 사라지면 정지·재탐색한다.
5. 그리퍼 PSD만 파지를 시작한다. 최신·유효 거리의 지속 감지, 실제 정지, 닫힘·유지 확인이 모두 필요하다. 좌·우·뒤 PSD는 파지 트리거가 아니다.
6. 확보 후 현재 지도로 출발점에 복귀한다. 상대 로봇·막힌 경로는 재계획하며, 유지 상실이 확인되면 정지 후 재탐색한다.
7. 규정 14의 운송 완료는 개방을 명시적으로 요구하지 않는다. 도착 후 주행 정지·확보 유지가 기본 초안이며, 기존 설계의 `RELEASE` 필요 여부는 심판 판정 확인 후 정한다. 공개 후 사람이 설정을 바꾸는 방식으로 처리하지 않는다.

### 시간 관리와 실패 대응

10분 예산은 `시작 준비 + 탐색 + 접근/파지 + 복귀 + 실패 복구 여유 ≤ 600초`로 관리한다. 각 항목은 실물 반복 시험의 시간으로 정하며 임의 분 단위 배분을 확정하지 않는다. 복귀 예산은 현재 경로 길이·검증된 운반 속도·재계획 여유를 사용한다.

- 확보 중에는 남은 시간을 고려해 복귀를 우선한다. 목표물이 없는데 빈손 복귀하는 것을 유리한 종료 전략으로 취급하지 않는다.
- 규정 14의 시간 초과 판정은 **목표물과 자기 출발점의 거리**다. 로봇만 출발점으로 돌아가도 목표물이 그대로면 판정상 이득이 없다.
- 목표물을 자기 쪽으로 옮기는 전략은 가능성이 있지만, 기본 구현은 확인된 확보·운반으로 거리를 줄인다. 밀기는 목표물 방향만 아는 카메라와 장애물 손상 위험 때문에 별도 검증 전 제외한다.
- 재시도는 제한하며 감지 실패·닫힘 실패·유지 불명·놓침을 서로 구분한다. 센서 오류만으로 잡은 물체를 개방하지 않는다.

## 5. 미션2 전략 — 확보·연속 유지·코너 회피

`시작 잠금 → 벽 기반 위치 확인 → 중앙 우선 탐색 → 공통 접근/파지 → 유지 → 위험 시 안쪽 안전공간 이동 → 종료 시 파지 유지`

1. 네 출발점 중 어느 곳에서도 벽 관측으로 경기장 내부 방향·코너 영역을 판단한다. 정사각형의 회전 대칭은 중앙·네 코너 회피에는 같은 기하를 주지만, SLAM 원점만으로는 충분하지 않다.
2. 초기 중앙을 탐색 우선순위로 쓰되 카메라로 목표물을 재확인한다. 상대가 운반했거나 탈락 후 주변으로 재배치될 수 있다(규정 23).
3. 미션1과 동일한 PSD·정지·파지·유지 확인을 재사용한다. 상대 로봇의 근접만으로 자동 파지하지 않는다.
4. 확보 뒤에는 네 코너의 400 × 400 mm 영역을 로봇 외곽·추정 오차·제동 여유만큼 확장해 피한다. 금지영역은 Nav2 경로와 시각 서보 양쪽에 적용한다.
5. 주변 로봇을 완벽하게 식별하는 추적기보다 우선 가까운 물체를 피하고 안전공간을 유지한다. 정지한 상대도 장애물이다. 좌·우·뒤 PSD의 보조 역할은 모델·범위 확인 후 결정한다.
6. 엔코더가 정지해도 상대에게 밀릴 수 있다. LiDAR 위치 변화와 구동 상태를 함께 확인한다. 위치 신뢰도가 낮으면 위험 방향 명령을 제한하지만 정지만으로 밀림을 막을 수 없으므로 접촉 시험을 통과해야 한다.
7. 300초 종료 시 주행을 정지하고 그리퍼는 유지한다. 재경기 180초 모드는 사전 준비하고 허용 시작 명령으로 선택 가능한지 확인한다. 시간은 온보드 단조 시계로 측정한다.
8. 재경기의 연속 확보 시간 판정(규정 26)을 고려해 불필요한 개방을 피한다. 확보/놓침 시각은 온보드 기록하되 자체 로그가 심판 판정을 대신하지 않는다.

미션2 경량 순위는 조별 우승팀 이외의 순위에 적용된다(규정 27). 무조건 중량을 늘리거나 무조건 가볍게 만들기보다, 확보 안정성·접지력·전원 지속을 먼저 검증하고 불필요한 무게를 제거한다.

## 6. 구현 순서와 단계 통과 조건

날짜 대신 선행 조건으로 진행한다. 각 단계가 실패하면 상위 전략을 추가하기 전에 원인을 해결한다.

| 순서 | 작업·영향 영역 | 통과 조건 |
|---|---|---|
| P0 | 최종 규정·시작 절차·판정 질문 정리, 최대 외곽·무게·통로 확인 | 동일 하드웨어가 규격과 실제 통로 요구를 충족, 규정 해석 미확정 항목 식별 |
| P1 | UART·주행·정지: `cwu_base`, Nucleo, `cwu_slam` 장착 | 모터 부하 상태 통신, 단절/명령 만료 실제 정지, 제동거리·오도메트리 반복 측정 |
| P2 | 공통 확보: `cwu_perception`, `cwu_nav/target_follower`, PSD·그리퍼 | 다양한 조명에서 목표물 정렬→PSD→정지→파지→들어올림·운반 재현 |
| P3 | 임무 연결·속도 선택·위치 추정: `cwu_nav`, 미션/안전 제어 | 명령 주체 하나만 활성, 전환 때 정지, 센서 만료·실패·코너 제한이 모든 주행 경로에 적용 |
| P4 | 미션1 탐색·복귀 | 양 출발 조건·미지 장애물 배치에서 사람이 목표 지정하지 않고 600초 안에 운송 |
| P5 | 미션2 유지·탈락 회피 | 네 출발 조건·물체 가림·밀림·놓침 재확보에서 코너 진입 없이 종료 시 실제 확보 |
| P6 | 경기 구성 확정·온보드 단독 리허설 | 외부 통신 차단, 설정 수정 없이 양 미션 수행, 코드/YAML·하드웨어 명세 보관 |

PSD 모델·그리퍼 기구·유지 피드백 결정은 P1과 병행한다. 사양이 없는 상태에서 거리 환산식·전압·핀·파지력을 추측해 구현하지 않는다.

새로 필요한 책임은 미션 상태 전이, 경기장 정합, 속도 명령 선택, PSD 파지다. 기존 패키지와 표준 `NavigateToPose`, `/scan`, `/odom`, TF, `/target/bearing`, `/cmd_vel_safe`를 재사용하며 각 책임마다 새 패키지를 기계적으로 만들지는 않는다. PSD의 `sensor_msgs/Range`는 기존 초안을 따르고 최종 MCU 필드는 하드웨어 확정 후 정한다.

## 7. 검증 계획

아래 횟수·오차는 대회 의무가 아닌 **팀의 초기 개발 합격 기준 제안**이다. 안전 여유·속도·센서 임계값은 실측 후 공개 전에 YAML로 확정한다.

| 시험 | 최소 확인 내용 |
|---|---|
| 하드웨어 없는 검사 | 상태 전이, 오래된 카메라/PSD, 무효 거리, 명령 전환, 정지 실패, 닫힘 실패, 유지 불명, 놓침, 모든 상태에서 종료 |
| 빌드·ROS 통합 | 구현 시 영향 패키지 `colcon build`·`colcon test`, 토픽 타입·QoS·프레임·타임스탬프, `/odom`/TF 중복 발행 없음 |
| 주행 | 기존 제안 유지: 1m 직진·360도 회전 각3회, 거리오차≤5%·방향오차≤5도. 별도로 최악 제동거리 측정 |
| 통로 | 실제400 mm 통로·교차로에서 최대 외곽을 포함해 비접촉 통행, 불가 경로에서는 정지 |
| 확보 | 실제50 mm·약100 g 큐브, 접근·파지·들어올림·운반을 최소10회 기록. 다른 물체·가림·근접 화면 이탈 포함 |
| 미션1 | 시험자가 준비한 서로 다른 미공개 점대칭 배치 최소3개, 양 출발 조건, 설정 변경 없이 시간·충돌·확보·복귀 기록 |
| 미션2 | 네 출발 조건, 이동/정지 물체, 벽 가림, 통제된 밀림, 목표물 재배치, 300초/180초 종료·유지 확인 |
| Pi 동시 부하 | 경기 구성으로 최소10분 실행. 지연이 입력 만료·제동 여유를 침범하지 않고 메모리 부족·프로세스 재시작 없이 동작 |
| 통신 차단 | 개발 중 허용 시작 절차를 재현하고 PC 로그아웃·외부 통신 차단 후 자율 동작 지속. 본 경기는 외부 기록 장치에 의존하지 않음 |

시험마다 날짜·코드/펌웨어 버전·YAML 사본·온보드 로그·실측 결과를 남긴다. 작은 표본 성공은 전체 경기 신뢰성을 증명하지 않으므로 실패 원인과 재현 조건도 함께 기록한다.

**이번 작업의 검증 범위:** 규정·기존 문서·런치 연결 확인과 문서 링크/형식 검사. 실행 코드는 변경하지 않았으므로 빌드·실물 시험은 이번에 수행하지 않았다.

## 8. 열린 질문과 검토 요청

### 주최 측 확인이 필요한 항목

- 최종 확정 규정이 저장소의 규정(안) 요약과 같은가?
- 허용 실행 명령으로 미션·180초 재경기 모드 선택이 가능한가? 통신 모듈 차단 시점·방법은 무엇인가?
- 미션1 운송 완료의 위치 허용 범위·그리퍼 개방 필요 여부는 무엇인가?
- 센서 관측으로 생성한 런타임 지도·경로와 프로그램의 자동 상태 갱신이 허용되는 범위는 무엇인가? 참가자의 파일·파라미터 변경은 하지 않는다.

### 팀 실측·선택이 필요한 항목

- 최대 확장 외곽·실제 통로 여유·배터리 포함 질량은 얼마인가?
- UART 전환 후 실제 펌웨어·Pi 포트·모터 노이즈 조건의 안정성은 확인됐는가?
- PSD 모델·전압·범위·배선·거리 보정, 그리퍼 구동기·유지 피드백은 무엇인가?
- 정렬부터 PSD 감지까지 목표물이 카메라에 계속 보이는 장착 pitch와 접근 조건은 무엇인가?
- Pi 전체 부하, 벽 기반 위치 오차, 제동거리로 산정한 코너 여유는 얼마인가?

Claude는 규정 위반·연결 불가·하드웨어 제약 초과·과설계 여부를 검토하고 직접 수정한다. 이 문서는 검토를 통과했다고 주장하지 않는다.
