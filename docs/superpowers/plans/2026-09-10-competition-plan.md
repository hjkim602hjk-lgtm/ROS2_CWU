# 대회 로봇 구현 계획 (미션1/미션2)

**갱신일:** 2026-09-16
**상태:** codex 초안 — Claude 검토 및 실물 검증 대기
**근거:** `Agent.md`, `docs/competition_rules.md`, `README.md`
**선행 산출물:** `docs/superpowers/plans/2026-09-08-slam.md` (cwu_slam 완료)

> [!info] 계획과 현재 상태 구분
> 로컬 구현을 기준으로 갱신했습니다. `cwu_base` 등은 Git 미추적 상태이며 커밋된 결과와 구분합니다.
> 실물 주행 합격은 아직 아닙니다. 이후 단계는 프로토콜·기구 사양을 확보한 뒤 상세 설계합니다.

## 0. 이번 갱신에서 바뀐 것

그리퍼에 PSD 센서를 장착하고 설정 거리 이내 물체를 감지하면 자동 파지하는 방식으로 변경했습니다.
D415가 목표물 확인·접근을 맡고, PSD가 마지막 근접 감지와 파지 시작 조건을 맡습니다.
미션1·미션2 모두 같은 PSD·그리퍼를 사용합니다. 센서 모델·거리 임계값·구동기·피드백은 실측 확정 전입니다.
상세 흐름과 인터페이스 초안은 [[docs/superpowers/specs/2026-09-16-psd-gripper-design|PSD 자동 파지 설계]]를 따릅니다.
기존 SLAM 백엔드와 엔코더 검증 순서는 유지합니다.

## 1. 규칙에서 도출한 확정 제약

### 1.1 시간
- 미션1: **10분**, 미션2: **5분** (동시확보 시 3분 재경기)
- 10분 안에 탐색·접근·파지·복귀 전부. 속도 예산이 설계 변수입니다.

### 1.2 경기장
- 3600×3600 mm, 9×9 격자(각 400 mm), 외벽 높이 **200 mm**
- 장애물 400×400×**200 mm**, 격자 정렬, 간격 400 mm 배수, `(5,5)` 점대칭 배치
- 경기장·장애물 모두 회색 `RGB(127,127,127)`, 타겟은 무광 빨강 `RGB(255,0,0)`

### 1.3 하드웨어 제약 (신규 도출 — 중요)
1. **LiDAR 장착 높이 < 200 mm.** 벽과 장애물이 모두 200 mm입니다. G4가 그보다 높으면 아무것도 안 보입니다. 권장 100–150 mm.
2. **그리퍼는 "들어올려도 함께 들리는" 파지**여야 합니다 (규정 19항). 스쿠프·밀기·단순 접촉은 미션2에서 확보로 불인정.
3. 경량화가 미션2 순위 가산 (규정 27항: 같은 조 내 순위는 더 가벼운 로봇 우선).
4. Ø400×300 mm, 10 kg, 부품 분리 금지, 날카로운 외형 금지.

**팀 설계 결정:** PSD는 그리퍼에서 목표물이 들어오는 위치를 보도록 장착합니다.
센서·배선·그리퍼를 포함한 최대 확장 크기와 질량을 검증합니다. PSD 채택 자체는 대회 의무 규정이 아닙니다.

### 1.4 시작 위치
- 미션1: `(1,9)` 또는 `(9,1)` / 미션2: `(2,2) (2,8) (8,2) (8,8)`
- **어느 위치를 배정받는지는 사전에 모릅니다.** 좌표를 하드코딩하지 말고 부팅 시점 SLAM 원점을 시작점으로 기억합니다.

## 5. 단계 계획

### Phase 1a — 실물 엔코더·SLAM 검증 ★최우선

1. 모터 전원을 분리하고 Nucleo 포트를 `/dev/serial/by-id/`에서 식별합니다. 기존 스니퍼를 명시적 포트로 실행하고 출력을 보관합니다.
   `python3 tools/sniff_encoder_serial.py /dev/serial/by-id/<Nucleo-ID> | tee /tmp/encoder-sniff.txt`
   스니퍼의 보드레이트·필드 판정은 후보입니다. 좌우 바퀴를 각각 앞뒤로 움직여 원시 출력과 대조합니다.
2. 정지·좌측만·우측만 움직이는 구간에서 누적 틱 필드, 부호, 카운터 폭, 전송 주기를 확인합니다.
   카운터 폭은 펌웨어 또는 되감김 관측으로 확인합니다. 스니퍼 요약만으로 확정하지 않습니다.
3. 반지름·좌우 접지점 간격과 좌우 각각 바퀴 10회전의 틱 변화량을 측정합니다.
   `ticks_per_rev = 틱 변화량 / 10`. 좌우 환산값이 다르면 기존 공통 제원 모델의 적합성부터 검토합니다.
4. `src/cwu_base/config/encoder.yaml`에 확인한 값만 입력합니다. `baud: 115200`, 부호, `counter_bits: 32`도 실측 확정값이 아닙니다.
   바이너리라면 원시 프레임을 확보한 뒤 파서를 수정합니다.
5. `src/cwu_slam/config/mount.yaml`에 실제 x/y/z와 roll/pitch/yaw를 입력합니다.
   정면·좌측 물체의 표시 방향, 벽·장애물을 볼 수 있는 측정면 높이를 확인합니다.
6. README 실물 launch로 안전하게 수동 이동합니다. 1 m 직진과 360° 회전을 각각 3회 수행하고,
   각 회차 직진 거리 오차 ≤5%, 회전 후 방향 오차 ≤5°를 초기 개발 합격 기준으로 둡니다.
   시작·끝 자세와 연속 yaw의 누적 회전각을 기록해 0° 이동을 360° 회전으로 오판하지 않습니다.
7. `/scan`, `/odom`, `map → odom → base_link → laser_frame`, 지도 갱신·저장을 확인합니다.
   정지 중 `/odom` 주기도 확인합니다. MCU가 정지 표본을 보내지 않으면 현재 TF도 갱신되지 않습니다.

실물 실행 중 별도 온보드 터미널에서 기록합니다(개발 시험용):

```bash
mkdir -p measurements
ros2 bag record -o measurements/manual-slam-01 /scan /odom /tf /tf_static /map
# 종료 후 README의 map_saver_cli로 같은 시험 이름의 지도를 저장합니다.
```

각 실행은 새 기록 이름을 사용하고 launch 로그, 사용한 YAML 사본, 스니퍼 출력도 함께 보관합니다.
이 bag의 `/tf`에는 SLAM 출력 `map → odom`도 있으므로 새 SLAM 입력으로 그대로 재생하지 않습니다.
README 재생 예제처럼 입력 TF만 남기고 `start_encoder:=false`로 중복 발행을 방지합니다.

| 측정 항목 | 결과 / 근거 파일 |
|---|---|
| 날짜·보드/펌웨어·포트·baud·프레임 예시 | 미측정 |
| 좌/우 필드·부호·카운터 폭·정지/이동 전송 주기 | 미측정 |

**완료 조건:** 미측정 설정 해소, 반복 측정 합격, 실제 지도 생성·저장 재현.
보정은 경기장 공개 전에 완료하며 공개 후에는 센서로 환경에 적응합니다(규정 36절 Rule 1–4).

### Phase 1b — 모터 제어와 안전 정지 (구현 초안, 실물 미검증)

현재 구현·변경 파일·측정 과제는 [[docs/superpowers/plans/2026-09-29-nav2-drive-status|구동 구현 기록]]을 따른다.
최종 입력은 `/cmd_vel_safe`이며 구동 기본값은 비활성이다.

- 기존 `cwu_base`와 기구학을 재사용합니다. Nucleo PI 제어와 설정 확인 프로토콜을 구현하고 `/cmd_vel_safe`를 연결했습니다. 실물 검증은 남아 있습니다.
- MCU 명령 타임아웃을 포함해 명령 만료·통신 단절 시 실제 정지를 구현합니다.
- PSD와 그리퍼가 Nucleo를 공유하면 한 시리얼 수신 경로에서 엔코더·거리·구동 상태를 구분합니다. 기존 `encoder_odom`과 새 노드가 같은 포트를 동시에 읽지 않게 합니다.
- **완료 조건:** 전진·후진·회전 및 명령 만료·연결 단절의 실제 정지 검증.

### Phase 2 — Nav2 통합 (새 코드 최소) — **설정·런치 작성 완료, 실행 미검증**
- `nav2_bringup` 기성품 + YAML만. 플래너/컨트롤러 자작 금지. → `src/cwu_nav` 로 구현.
- 컨트롤러는 Regulated Pure Pursuit을 골랐습니다. DWB의 궤적 샘플링이 Pi 4에서 비쌉니다.
- 가상 검증 수단을 함께 만들었습니다: `demo_sensors`에 `/cmd_vel` 주행 모드를 추가해
  SLAM → Nav2 → `/cmd_vel` → 실제 이동 → 복귀까지 하드웨어 없이 확인합니다
  (`src/cwu_nav/test/run_nav2_check.py`). 기존 고정 원운동 데모의 한계를 이것으로 대체합니다.
- **2026-09-16 검사 통과:** (0.93, -0.73) 도달 오차 0.10 m, 원점 복귀 오차 0.09 m,
  상자 안 목표 ABORTED(코스트맵이 장애물을 실제로 막음).
- 검사 과정에서 설정 오류 셋을 잡았습니다: 컨테이너 없는 `use_composition`(Nav2가 조용히
  하나도 안 뜸), `local_costmap.width` 소수(정수여야 함), `bt_navigator.plugin_lib_names`
  하드코딩(기본 BT가 쓰는 노드 누락). 상세는 미션1 제어 설계 문서에 있습니다.
- **남은 것: 실물 `/scan`에서의 코스트맵 동작과 Pi 4 자원 측정입니다.**
- 3.6 m 경기장에 맞춘 코스트맵 해상도, 인플레이션, 풋프린트(Ø400 mm).
- 온라인 SLAM과 동시 실행 (사전 지도 금지 제약 충족).
- **이 단계의 진짜 산출물은 Pi4 4GB CPU/메모리 예산 측정입니다.** SLAM + Nav2 + D415가 동시에 못 돌면 이후 설계가 전부 바뀝니다.
- **검증**: `/cmd_vel`에 반응하는 시험 환경에서 Nav2 표준 이동 액션으로 목표점 이동·장애물 회피·출발점 복귀. 기존 데모는 고정 원운동이므로 이 검증을 대체하지 못합니다. SLAM·Nav2·D415 동시 실행 시 Pi 4 CPU·메모리·온도·처리 지연을 기록합니다.
- 복잡도 **소~중**, 성능 리스크 **높음**.

### Phase 3 — `cwu_perception`: 적색 타겟 검출 — **구현 완료, 실물 카메라 미검증**
- D415 컬러 HSV 임계 + 면적/종횡비/채움비 필터 → 단위 방향 벡터 → `/target/bearing`.
  **2026-09-16 변경:** 카메라가 깊이를 측정하지 않기로 확정되면서 `/target/pose`(3D 위치)를
  `/target/bearing`(방향)으로 바꿨습니다. 거리는 그리퍼 PSD가 맡습니다.
- 좌표는 카메라 컬러 광학 프레임 그대로 발행합니다. `base_link` 변환은 소비자가 TF로 합니다.
  검출기 안에서 변환하면 검출 실패와 장착 보정 실패가 같은 증상으로 섞입니다.
- 424×240 @ 15 fps 컬러만. 깊이 스트림·정렬·포인트클라우드 전부 끔 (Pi 4 동시 실행 예산).
- 딥러닝 없음. 회색 경기장 위 무광 빨강 단색 큐브에 CNN은 Pi4 예산 낭비입니다.
- 조명 강건성: 자동 화이트밸런스·노출 **고정**, HSV 범위는 넓게, 다조명 사전 검증으로 흡수. 경기장 공개 후 튜닝은 규정상 금지입니다.
- 50 mm 큐브는 원거리에서 화소 수가 적습니다. 검출 유효 거리를 실측해 미션 로직의 접근 거리 임계로 씁니다.
- D415는 목표물 확인·정렬과 접근을 맡습니다. 그리퍼 개구부 안으로 접근한 물체의 마지막 거리 감지는 PSD로 넘기며, PSD만으로 빨간 목표물임을 판정하지 않습니다.
- **검증**: 여러 조명에서 촬영한 정지 이미지 세트로 순수 함수 테스트(카메라 불필요).
- 복잡도 **중** — 알고리즘은 작고 조명 강건성이 실제 비용.

### Phase 4 — `cwu_gripper`: PSD 거리 감지 기반 자동 파지

- **확정 흐름:** 그리퍼에 PSD 장착 → 설정 거리 이내 물체 감지 → 자동으로 집기.
- **통합 초안:** 목표물 확인·정렬 후 파지를 활성화하고 저속 접근합니다. 유효한 PSD 근접 감지가 설정 시간 동안 지속되면 주행을 정지하고, 정지 및 거리 조건을 확인한 뒤 닫습니다.
- PSD 입력은 센서 사양에 맞춰 온보드에서 읽습니다. 거리 토픽은 `/gripper/range` (`sensor_msgs/msg/Range`, m 단위)를 초안으로 두고, Nucleo 연결 방식·프레임은 실물 확인 후 확정합니다.
- 파지 활성화/해제·개방 요청과 개폐 진행·유지·오류 상태를 연결합니다. 액추에이터 피드백에 맞춰 서비스/액션을 결정합니다.
- 거리 임계·확인 시간·입력 만료·접근/정지/구동 시간 제한·구동기 제한·재시도 한도는 YAML로 관리합니다. 미측정 필수값이 있으면 자동 파지 활성화를 거부합니다.
- **PSD 감지는 파지 시작 조건입니다.** 완료·유지 판정에 사용할 피드백은 D 확정 때 결정합니다. 미션2의 성공 기준은 실제로 들어도 목표물이 함께 들리는 것입니다(규정 19항).
- 탐색·개방 중에는 자동 파지를 비활성화합니다. 센서 오류나 목표물 조건 상실 시 접근을 정지하고, 닫는 중에는 중복 명령을 차단합니다. 유지 중 센서 오류만으로 자동 개방하지 않습니다.
- 이동 중 유지·탈취 대응(규정 13, 20항)은 유지 피드백으로 판단하고, 놓침이 확인되면 재탐색·재접근합니다.
- **검증:** 거리 경계·노이즈·무효/오래된 입력·정지 실패·시간 초과·중복 닫힘·개방 후 재파지 방지의 하드웨어 없는 상태 전이 검사, 실물 거리/파지/들어올리기/운반 시험.
- 전제: 미지수 D·E와 Phase 1b의 실제 정지·통신 경로. 상세 내용은 [[docs/superpowers/specs/2026-09-16-psd-gripper-design|PSD 자동 파지 설계 초안]].

### Phase 5 — `cwu_mission1`: 자율탐색 및 구출 (10분)
상태머신: `GO_CENTER → SEARCH → APPROACH → GRASP → RETURN → RELEASE`

- **`GO_CENTER`**: 먼저 온보드 센서로 경기장 좌표계를 추정해야 합니다. SLAM 원점만으로 중앙·코너를 알 수 없습니다. 추정 전에는 탐색합니다. 타겟 초기 위치 `(5,5)`는 규정 명시값이므로 중앙을 첫 목표로 잡습니다. 장애물 배치는 미지이지만 Nav2 + 온라인 SLAM이 실시간으로 회피합니다. 전면 탐색보다 훨씬 빠릅니다.
- **`SEARCH`**: 중앙에서 목표물을 찾지 못했거나 접근·파지·운반 중 놓친 경우 재탐색합니다. 프론티어 탐색 또는 격자 스윕을 사용합니다.
- **`APPROACH`**: D415로 확인한 목표물을 정렬하고 그리퍼를 개방한 뒤 PSD 자동 파지를 활성화합니다. 저속 접근 중 유효한 거리 조건이 지속되면 `GRASP`로 전이합니다. 입력 불능·목표물 조건 상실·시간 초과 시 정지하고 재탐색합니다.
- **`GRASP`**: 정지 확인과 PSD 조건 재확인 후 닫고, 파지 완료·유지를 확인한 경우에만 `RETURN`으로 전이합니다. 실패 시 정지 상태에서 제한된 재시도 또는 재탐색을 판단합니다.
- **`RETURN`**: 부팅 시 저장한 `map` 프레임 시작 좌표로 복귀. 좌표 하드코딩 없음. 유지 피드백으로 놓침이 확인되면 정지 후 `SEARCH`로 전이합니다.
- **`RELEASE`**: 시작점 도착 후 파지를 비활성화하고 개방합니다. PSD가 가까운 목표물을 계속 감지해도 자동으로 다시 닫지 않습니다.
- 상대 로봇은 SLAM 지도에 없는 이동 클러스터로 처리 → 코스트맵 동적 장애물. 접촉해도 임무는 계속.
- 10분 예산 배분과 타임아웃 전이(예: 남은 시간 부족 시 무조건 복귀) 포함. 규정 14항상 시간 초과 시 타겟-시작점 거리로 승패가 갈리므로, **못 잡을 것 같으면 타겟을 자기 시작점 쪽으로 밀어두는 것도 유효 전략**입니다.
- 안전 감시자: `/cmd_vel` 게이트 — LiDAR 근접 정지, 명령 타임아웃, 경기장 경계 초과, 장애물 밀기 금지(규정 7.1항 실격).
- **검증**: 상태 전이 순수 테스트 + 데모 환경 종단 리허설. 복잡도 **대**.

### Phase 6 — `cwu_mission2`: 배틀럼블 (5분)
- 중앙 접근 → D415 목표물 확인·정렬 → PSD 거리 감지 → 정지·파지 → 유지. 미션1의 `GO_CENTER`/`APPROACH`/`GRASP`와 동일한 파지 조건을 재사용합니다.
- 실제 유지가 확인된 뒤 유지 상태로 전이합니다. 놓침이 확인되면 재탐색·재접근하며, 상대 로봇이 PSD에 가까워지는 것만으로 그리퍼를 작동시키지 않습니다.
- **코너 탈락 회피**: 네 모서리 격자(400×400)를 코스트맵 금지구역으로. 시작 시 SLAM으로 벽 4면을 잡아 경기장 좌표계를 정렬하면 모서리는 계산으로 나옵니다. 좌표 하드코딩 불필요.
- 상대 로봇 검출: LiDAR 클러스터링(수십 줄). 벽은 지도로 알고 있으므로 그 외 이동 클러스터가 상대.
- 밀림 감지(명령 대비 오도메트리 불일치) → 중앙 복귀.
- 하드웨어 동일 제약(규정 4.4)상 소프트웨어·런치만 분리. 복잡도 **중**.

### Phase 7 — 통합 리허설
- 외부 PC 미연결 상태 재현, 부팅 자동시작 + 실행 명령 1회 수신 후 통신 차단.
- 배터리 지속시간, 질량·치수 실측(10 kg / Ø400×300), 10분·5분 풀런.
- PSD 장착·배선을 포함해 두 미션의 하드웨어가 동일한지 확인합니다. 목표물 접근·감지·정지·파지·유지·해제와 센서 단절 시험을 양 미션에 포함합니다.
- 규정 30항: 팀원이 하드웨어·소프트웨어 구성을 설명할 수 있어야 합니다.

## 6. 의존성 순서

```
[미지수 B,C 확정 / D,E 기구·센서 시험 병행]
   └→ Phase 1 (베이스) → Phase 2 (Nav2) ─┬→ Phase 5 (미션1) ─┐
                          Phase 3 (인지) ─┤                   ├→ Phase 7
                      Phase 4 (PSD·그리퍼) ┴→ Phase 6 (미션2) ─┘
```

D415 데이터 확보, PSD 거리 측정과 그리퍼 기구 시험은 주행 개발과 독립적으로 진행합니다.
Phase 4의 자동 접근·정지·파지 통합은 Phase 1b의 실제 정지와 MCU 통신을 선행 조건으로 둡니다.
