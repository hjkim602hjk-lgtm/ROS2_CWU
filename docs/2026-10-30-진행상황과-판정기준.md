# 진행 상황과 판정 기준 (2026-10-30)

대회 판정 기준과 지금까지의 진행 상황을 한 문서로 모았습니다. 판정 기준의 근거는 [[docs/competition_rules|대회 규정]]이고,
조항 번호는 그 문서의 절 번호입니다. 실물 시험의 자세한 수치는 [[docs/2026-09-29-실물-주행-시험-기록|실물 주행 시험 기록]]에 있습니다.

> [!note] 기준 시점
> 2026-10-30, 브랜치 `integrate-camera`, HEAD `07bc3a0` + 커밋 안 된 작업본(15개 파일). 작업본 내용은 따로 표시했습니다.

## 1. 한눈에 보기

| 영역 | 상태 | 비고 |
|---|---|---|
| 하드웨어 구성 | 동작 | Pi 4 + Nucleo F446(UART4 직결), G4 라이다, USB 웹캠, PSD 4개, 서보 집게 2개 |
| Pi ↔ 보드 통신 | 동작 | ST-Link USB가 모터 잡음에 멈추던 문제 → PC10/PC11 UART 직결로 해결 |

| 경기 운용(통신 차단·시작 절차) | 미검증 | 무선 차단 후 임무 지속, 시작 전 무동작 리허설 안 함 |

## 2. 대회 판정 기준

### 2.1 미션 1 — 자율탐색 및 요구조자 구출 (9~14절)

| 항목 | 기준 |
|---|---|
| 경기 방식 | 2팀 1조, 조별 우승팀끼리 토너먼트 (9.1) |
| 제한 시간 | **10분** (9.2) |
| 시작 위치 | `(1,9)` 또는 `(9,1)`. 구동 후 외부 통신 차단 (9.3) |
| 경기장 | 3600 × 3600 mm, 9 × 9 격자(칸 400 mm), 장애물은 `(5,5)` 기준 **점대칭**, 배치는 로봇·PC 수거 후 공개 (10) |
| 목표물 | 무광 빨강 50 mm 정육면체, 약 100 g, 초기 `(5,5)`, **고정 안 됨** (12) |
| 이동·탈취 | 목표물을 옮기는 데 제한 없음. 상대가 확보한 목표물도 빼앗을 수 있음 (13) |
| **정상 승리** | 목표물을 **자신의 시작 위치까지 먼저** 운송한 팀 (14) |
| **시간 초과** | 둘 다 못 하면 **시작 지점과 목표물 사이 상대 거리가 더 가까운 팀** 승리, 심판 판단 (14) |
| **동일 거리** | 시간 초과 + 상대 거리 같으면 **양 팀 모두 탈락** (14) |

**우리에게 주는 의미**
- 운송 완료가 최우선이지만, 실패해도 **목표물을 들고 출발점 쪽으로 최대한 가까이 와 있는 것**이 승패를 가른다. 10분 안에 못 돌아와도 들고 있으면 유리하다.
- 목표물이 `(5,5)`에 그대로 있다는 보장이 없다(상대가 건드릴 수 있음). `(5,5)`를 힌트로 쓰는 것은 허용되지만, 없으면 탐색을 이어 가야 한다.
- 장애물 배치는 미리 넣으면 안 된다(31절 "미지 환경 대응"). 경기장 크기·출발 칸·초기 목표 위치는 규정에 공개된 값이라 써도 된다.

### 2.2 미션 2 — 배틀럼블 (15~27절)

| 항목 | 기준 |
|---|---|
| 경기 방식 | 4팀 동시, 조별 우승팀끼리 토너먼트, 조 구성은 당일 결정 (15) |
| 제한 시간 | **5분** (16) |
| 시작 위치 | `(2,2)`, `(2,8)`, `(8,2)`, `(8,8)`. 내부 장애물 없음 (17) |
| **확보 판정** | 로봇을 지면에 수직으로 들어 올렸을 때 **요구조자가 함께 들리면 확보**. 접촉·밀기만으로는 인정 안 될 수 있음 (19) |
| 탈취·접촉 | 탈취 허용, 상대 로봇 밀기 허용, **고의 파손 금지** (20, 21) |
| **탈락 영역** | 경기장 **모서리 격자**. 들어가면 즉시 탈락 가능, 절반 이상 들어가면 심판 판단 (22) |
| 탈락 시 | 들고 있던 요구조자는 중앙 원위치로 재배치 (23) |
| **승리** | 종료 시점에 **요구조자를 확보하고 있는 로봇** (24) |
| 동시 확보 | 둘 이상이 동시에 들리면 **3분 재경기** (25) |
| 재경기도 동시 | **종료 시점부터 거꾸로 셌을 때 연속 확보 시간이 가장 긴 팀** 우승. 놓쳤다 다시 잡으면 다시 잡은 시점부터 (26) |
| 조 내 순위 | 조 우승팀 외에는 **배터리 포함 무게가 가벼운 팀**이 높음 (27) |

**우리에게 주는 의미**
- PSD로 멈춰 집게를 닫은 것만으로는 확보가 아니다. **들어 올렸을 때 같이 들려야** 한다 → 집게 파지력·형상을 실물로 확인해야 한다.
- 승패는 "끝날 때 들고 있는가"와 "얼마나 오래 연속으로 들고 있었나"다. 잡은 뒤에는 빼앗기지 않고 모서리를 피하는 것이 공격보다 중요하다.
- 무게는 **조 내 순위** 기준이다. 불필요한 무게는 줄이는 편이 낫다.

## 3. 진행 상황

### 3.1 하드웨어·펌웨어 이력

| 날짜 | 내용 |

| 09-30 ~ 10-09 | UART 직결로 전환(Nucleo PC10/PC11 ↔ Pi GPIO14/15). 보드 한 번 무응답 → 여분으로 교체 |
| 10-11 ~ 10-12 | V3 펌웨어로 바퀴 속도 PI, odom·SLAM 보정 완료 |
| 10-14 | 팀원 `BASE_NAV_V1` 펌웨어(속도 명령 `[V]`, 20 Hz 텔레메트리). 집게 잡기 99/78, `[PF0]/[PF1]` 운반 모드 |
| 10-29 | 팀원이 새 `RobotIntegrated.ino` + `MotorControl.h`로 교체(이산 이동 `F`/`TL`/`TR`만). 이에 맞춰 Nav2를 빼고 격자 주행으로 재작성 |
| 10-30 (작업본) | 펌웨어에 BASE_NAV_V1 방식 속도 모드(`[ARM]`, `[V]`, `[N1]`)와 정면 PSD 60 ms 유지·운반 모드를 다시 넣는 중. **커밋·업로드 상태는 확인 필요** |

확정된 사실:
- 로봇 정면 = 집게·정면 PSD 쪽. 라이다는 거꾸로 장착(yaw 176.4°, inverted).
- 집게 열림 40/140, 잡기 99/78(사용자 확정). 펌웨어 변수는 팀원 값이 원칙이며 바꾸기 전에 확인한다.
- 큐브 없이 닫아도 정면 PSD가 약 579로 집게 날에 가려져, **정면 PSD로는 운반 중 놓침을 판별할 수 없다**. 현재 놓침 감지 수단 없음.
- 웹캠 USB 절전으로 멈추던 문제는 udev 규칙으로 해결.
- 기어비 때문에 로봇을 손으로 밀 수 없다.

## 4. 남은 일 (우선순위)

### 미션 1 (사용자 우선순위, 10-30 정리 — 코드 수정은 사용자 지시 후)
1. **탐색 완료를 웹캠이 본 칸 기준으로 판단.** 지금은 라이다로 채워진 칸을 탐색 완료로 쳐서, 카메라가 안 본 칸을 건너뛴다.
2. **탐색 중 작은 방향 오차는 무시하고 직진.** 제자리 진동도 같이 없어진다. 접근 단계의 정밀 조준(`align_deg`)은 유지.
3. **뚫린 길 연속 직진(CRUISE)과 출발 직후 바로 CRUISE** — 작업본에 있음, 실물 확인 필요.
4. 둘러보기 빈도, 라이다가 막았다고 본 칸이 경로를 끊는 문제.
5. 연습장 크기를 다시 맞춘 뒤 재시험. `grid_span`·출발 자세 확인.

### 미션 2
- 설계 초안 검토 → 확보 유지·모서리 회피·상대 감지 구현. 아직 시작 전.
- **확보 판정(들어 올리기) 실물 시험**: 집게로 큐브를 잡은 채 로봇을 들어 올려 같이 들리는지.

### 공통·경기 운용
- 운반 중 놓침 감지 수단(정면 PSD로는 불가).
- 무선 차단·원격 PC 로그아웃 후 임무 지속, 시작 신호 전 무동작 리허설.
- 최대 확장 크기(집게 연 상태) 400 × 300 mm 실측, 배터리 포함 무게 측정.
- Pi 전체 스택 10분 부하·온도 기록.
- 좌·우·뒤 PSD 용도 결정.

## 5. 우리 쪽 합격 기준 (실물 시험 판정)

대회 판정과 별도로, 실물 시험에서 "됐다"고 말하는 기준입니다. 로그만으로 판단하지 않고 실제 위치는 육안으로 확인합니다.

| 항목 | 합격 기준 | 현재 |
|---|---|---|
| 미션 1 완주 | 모의 경기장(미공개 배치 가정)에서 10분 안에 파지 → 출발 칸 복귀, 3회 연속 | Nav2 판 2회 성공, 현재 판 0회 |
| 복귀 정확도 | 출발 칸 중심에서 15 cm 이내 | 10-12 기준 19~20 cm |
| 벽·장애물 | 접촉·밀기 없음 | 현재 판 미확인 |
