# (이전 판) BASE_NAV_V1

작성일: 2026-10-14 (한국 시간)

이 문서는 `RobotNav_20261014.zip` 안의 `RobotIntegrated/RobotIntegrated.ino`를 기준으로 한다. 이전 V4 펌웨어에는 아래 속도 명령이 없으므로, 연동 전에 `h` 응답에 `# BASE_NAV_V1`이 있는지 확인한다.

## 1. 역할 분담

| 담당 | 작업 |
|---|---|
| STM 담당 — 선요한 | 펌웨어 업로드, 모터 방향·엔코더 확인, 거리·회전 보정, 바퀴 속도 PI, PSD 정지, 서보 제어 |
| Pi 담당 — 팀원 | UART 송수신, LiDAR, 오도메트리·TF, SLAM, 경로 계획(A* 등), 경로 추종, 목표/임무 관리 |
| 함께 확인 | 전진·회전 부호, 단위, 통신 끊김 정지, 40cm·좌우90도, 속도 추종, 실제 경로 테스트 |

팀원은 본인 Pi 코드를 그대로 발전시켜도 된다. 단, 이 문서의 UART 규약에 맞는 연결 부분을 구현해야 한다. 기존 Python 파일을 반드시 사용할 필요는 없다. 예제 `pi_nav_bridge.py`는 참고 구현이며, 팀원 프로그램과 동시에 같은 포트를 열지 않는다.

STM에 A*나 SLAM을 추가할 필요는 없다. Pi가 경로를 따라가기 위한 전진 속도·회전 속도를 계산하고 STM에 보낸다. A*가 만든 경로를 속도 명령으로 바꾸는 경로 추종 과정도 Pi에서 담당한다. 미탐색 영역의 다음 목표를 고르는 탐험 기능은 경로 탐색과 별도이다.

## 2. 통신 연결

| 항목 | 규격 |
|---|---|
| STM 보드 | NUCLEO-F446RE / STM32duino 3.0.0 기준 |
| 통신 | 3.3V TTL UART, 115200 baud, 8N1, 흐름 제어 없음 |
| Pi TX | STM PC11(RX)에 연결 |
| Pi RX | STM PC10(TX)에 연결 |
| 접지 | Pi와 STM 공통 GND |
| Pi 장치 | 현재 구성은 `/dev/serial0`; 실제 연결 장치에 맞게 지정 |
| USB | ST-LINK 업로드·디버그용. 아래 `[ARM]`, `[V…]`는 PC10/PC11 UART 입력에서만 허용 |
| 메시지 | ASCII. 명령 끝에 `\n` 권장. 응답은 줄 단위로 조립해서 처리 |

명령 내부에 공백을 넣지 않는다. 현재 펌웨어는 공백 자체를 즉시 정지 명령으로 해석한다. 예: `[V80,0]\n`은 정상, `[V80, 0]\n`은 정지한다. 소수점은 `.`을 사용한다. 한 번의 read가 한 줄과 같다고 가정하지 않는다.

## 3. 연결 후 초기화 순서

1. `q\n` 전송 → 기존 동작 정지·속도모드 허용 해제.
2. `h\n` 전송 → 버전·보정값 확인. 도움말은 정지 상태에서 출력된다.
3. `[N1]\n` 전송 → 정지 중에도 20Hz CSV 수신.
4. `# BASE_NAV_V1`, `# CAL,…`, `# TRACK_MM,…`와 정상 CSV를 확인.
5. 주행 준비가 되면 `[ARM]\n`을 한 번 전송.
6. `# ARMED`를 받은 뒤 새 속도 명령을 20Hz로 전송.

`# ROBOT40_V4 READY`는 호환용 부팅 문자열이다. 이것만으로 새 버전이라고 판단하지 않는다. `# BASE_NAV_V1`도 확인한다. `h` 응답의 보정 정보는 아래와 같다(소수점 반올림 허용).

```text
# BASE_NAV_V1
# TRACK_MM,190.400
# CAL,5.992624,5.900948
```

이 문자열 사이에 다른 도움말이나 CSV가 섞일 수 있다. 문자열 순서와 전체 줄 개수를 고정하지 않는다.

## 4. 자율주행 속도 명령

형식: `[V전진속도,회전속도]`

| 값 | 단위 / 부호 / 제한 |
|---|---|
| 전진속도 v | **mm/s**. 전진 +, 후진 −. 허용 범위 −150~+150 |
| 회전속도 w | **rad/s**. 위에서 볼 때 좌회전(반시계) +, 우회전 −. 허용 범위 −1.2~+1.2 |
| 전송 주기 | 권장 50ms(20Hz). 주행 중 마지막 유효 속도 명령 이후 300ms 초과 시 정지·disarm |

```text
[ARM]        → # ARMED 확인
[V80,0]      → 전진 80mm/s = 0.08m/s
[V-80,0]     → 후진 80mm/s
[V0,0.3]     → 제자리 좌회전 0.3rad/s
[V0,-0.3]    → 제자리 우회전 0.3rad/s
[V80,0.3]    → 전진하면서 좌회전
[V0,0]       → 속도모드 출력 정지, arm 상태 유지
q            → 모든 주행 모드 정지, arm 해제
```

위 예시의 설명 화살표나 공백을 UART에 보내지 말고 명령만 보낸다.

ROS의 `linear.x`가 m/s이면 UART 전송 전에 **×1000** 한다. `angular.z`는 rad/s 그대로 보낸다. 예를 들어 ROS `(0.08, 0.3)` → UART `[V80,0.3]\n`이다.

STM 내부 바퀴 목표는 `vL=v−w×190.4/2`, `vR=v+w×190.4/2`이다(mm/s). 바퀴 목표가180mm/s를 넘으면 양쪽을 같은 비율로 줄인다. 속도 제한으로 실제 속도가 요청보다 낮아질 수 있다.

`[V0,0]`은 속도모드를 정지시키는 명령이다. 진행 중인 `[F400]` 같은 별도 거리 모드를 취소하려면 **q**를 사용한다. PWM0은 출력 정지이며 실제 바퀴는 관성으로 조금 움직일 수 있다.

## 5. 정지와 재출발 처리 — Pi 담당 필수

- 주행 중 속도 명령이300ms 넘게 끊기면 `# ABORT VELOCITY_TIMEOUT`으로 정지하고 arm을 해제한다.
- `!` heartbeat만 보내도 속도 명령의 유효 시간이 연장되지는 않는다.
- PSD 감지, 엔코더 무응답·방향 이상, 속도 형식/범위 오류 등도 정지 원인이 된다.
- Pi는 `# ABORT …` 수신 시 명령 출력을 중단하고 원인을 표시한다. 원인 확인 후 명시적으로 다시 `[ARM]`을 요청한다. 자동 재무장은 하지 않는다.
- `# REJECT …`는 명령 거절이다. 모든 거절이 STM 정지를 뜻하지 않으므로, Pi는 상태가 불확실하면 **q를 전송해 정지**한다.
- Pi의 상위 경로 추종기가 멈췄는데 UART 송신 스레드가 예전 속도를 계속 보내면 STM은 새 명령으로 인식한다. 따라서 **상위 속도 명령 수신 후250ms를 넘기면 Pi가0속도 또는q를 보내는 watchdog**을 별도로 둔다.
- CSV 수신이500ms 이상 끊기면 Pi는q를 요청하고 연동 이상으로 처리한다. 이 시간은 팀원 구현에 필요한 권장값이며 STM 내부 조건과 별개이다.
- 부팅 메시지나 엔코더 초기화 메시지가 다시 나타나면 무장 상태를 해제하고 오도메트리 카운트 기준을 다시 잡는다.

처음 ARM 후 장시간0속도로 대기해도 arm상태는 유지될 수 있다. 사용이 끝났을 때는 `[V0,0]`만 남기지 말고q를 보낸다.

## 6. STM → Pi CSV

`[N1]`로20Hz, `[N0]`로 고속 스트림 해제. 기존 테스트 중에는 고속 스트림을 꺼도 기존200ms 주기의 CSV가 나올 수 있다. 헤더·도움말·상태 문자열이 섞인다. **12개 정수로 이루어진 줄만 텔레메트리로 처리**한다.

| 0부터 센 인덱스 | 값 | 의미 |
|---:|---|---|
| 0 | STM ms | 부팅 후 밀리초. 실제 날짜·시각 아님 |
| 1 | mode | 아래 모드표 참고 |
| 2 | ENC_L | 좌 누적 엔코더, 전진 증가 |
| 3 | ENC_R | 우 누적 엔코더, 전진 증가 |
| 4 | PWM_L | 좌 명령 방향을 포함한 signed PWM |
| 5 | PWM_R | 우 명령 방향을 포함한 signed PWM |
| 6 | PSD_FRONT | 정면 A0 raw ADC |
| 7 | PSD_REAR | 뒤 A1 raw ADC |
| 8 | PSD_LEFT | **왼쪽 A3** raw ADC |
| 9 | PSD_RIGHT | **오른쪽 A2** raw ADC |
| 10 | SERVO_L | 좌 현재 소프트웨어 명령 각도 |
| 11 | SERVO_R | 우 현재 소프트웨어 명령 각도 |

주의: CSV의 PSD 좌우 순서는 A0,A1,A2,A3 순서와 다르다. 서보 각도는 실제 축각을 측정한 피드백이 아니다. PSD raw값을 cm로 취급하지 않는다.

| mode | 의미 |
|---:|---|
| 0 | 정지 또는 목표 도달 후 정착 대기 |
| 1 / 2 / 3 | 좌 / 우 / 양쪽 모터 시험 |
| 4 / 5 | 시간제 / 연속 직진 동기화 PID 시험 |
| 6 | 과거 PSD AUTO용 예약. 새 펌웨어에서 `[AUTO]` 진입 거절 |
| 7 | 거리 주행 |
| 8 / 9 | 좌 / 우 목표각 회전 |
| 10 | Pi 속도 명령 제어 |

`mode=0` 한 줄만 보고 거리·회전 완료라고 판단하지 않는다. 해당 `# DONE …`을 기다린다.

## 7. 오도메트리 — Pi에서 계산

```text
counts_per_mm_L = (5687/1460) × (40/26) ≈ 5.992624
counts_per_mm_R = (5600/1460) × (40/26) ≈ 5.900948
effective_track_m = 0.1904

dL_m = (현재 ENC_L − 이전 ENC_L) / counts_per_mm_L / 1000
dR_m = (현재 ENC_R − 이전 ENC_R) / counts_per_mm_R / 1000
ds_m = (dL_m + dR_m) / 2
dtheta_rad = (dR_m − dL_m) / effective_track_m
```

회전 중에도 누적 엔코더 부호를 유지한다. 절댓값으로 바꾸면 회전 방향과 후진 오도메트리가 잘못된다. 첫 수신 시 누적값이0이 아닐 수 있으므로 첫 행은 기준으로만 저장한다. STM 재부팅·z명령·카운터 롤오버를 처리한다. uint32 STMms 롤오버는 차분을 modulo2^32로 계산하며, 재부팅 여부는 부팅 메시지·비정상 시간 간격 등도 함께 확인한다.

물리 윤거는206mm이고190.4mm는 오늘 제자리 회전으로 보정한 유효값이다. ROS측에도 현재 제어와 같은 유효값을 사용하되, 곡선·다른 바닥에서 다시 검증한다. 이 보정값만으로 SLAM 위치 정확도가 보장되는 것은 아니다.

ROS 사용 시 Pi 담당이 `/odom`과 `odom → base_link` TF를 제공한다. SLAM이 `map → odom`, 로봇 모델/정적 TF가 `base_link → lidar frame`을 제공한다. LiDAR 위치·방향은 실측값을 넣고, 동일 TF는 한 노드만 발행한다. EKF가odom TF를 발행하면 별도 UART브리지는 그 TF를 중복 발행하지 않는다.

## 8. 기존 거리·회전 시험

속도 스트림과 거리·회전 명령을 섞지 않는다. 먼저q로 정지한 다음 시험한다. Pi에서 아래 시험을 시작할 때 `!`를 먼저 보내고, 종료까지200ms마다 계속 보낸다. 마지막heartbeat 이후700ms 초과 시 정지한다. 테스트 모드 진입은 속도모드arm을 해제한다.

| 명령 | 동작 | 정상 완료 문자열 |
|---|---|---|
| `[F400]` | 400mm 전진 | `# DONE DISTANCE_400` |
| `[F1000]` 또는 `f` | 1000mm 전진 | `# DONE DISTANCE_1000` |
| `[F500]` 등 | 100~1000mm 전진 | 기타 거리: `# DONE DISTANCE` |
| `[TL90]` | 좌90도 | `# DONE TURN_LEFT` |
| `[TR90]` | 우90도 | `# DONE TURN_RIGHT` |
| `[TL45]` 등 | 좌/우10~180도 | 해당 방향 DONE |
| `p` | 직진 동기화 PID10초 | `# DONE TIMED_TEST` |

거리·회전 모드는 최대15초 제한이며 목표 도달 후300ms 정착 구간을 둔다. 목표각 추정 출력 `# TURN_EST_DEG`는 같은 보정 모델에서 계산된 값으로 독립 실측각이 아니다.

## 9. 서보·PSD

정지 상태에서 `7` 또는 `c`:열기(좌40°,우140°), `8`:잡기(좌99°,우78°; 2026-10-14 105/75에서 오른쪽 서보가 떨려 3°씩 완화, 2026-10-15 왼쪽 3° 더 완화). `[L105]`, `[R075]`는 세 자리 각도 형식이다. 실제 업데이트는1도/30ms이며, 움직이는 동안 새 주행 시작이 거절될 수 있다. CSV 각도가 목표와 일치한 뒤 다음 동작을 요청한다. 별도의 집게 물체 감지/파지 완료 센서는 구현되어 있지 않다.

**운반 모드 (2026-10-14 추가):** `[PF0]` → `# FRONT_PSD_OFF`, `[PF1]` → `# FRONT_PSD_ON`. 속도 모드에서 정면 PSD 정지 검사만 끄고 켠다(좌·우·뒤 검사는 그대로). 집게로 큐브를 문 뒤에는 큐브가 정면 PSD 앞에 있어 전진·회전이 모두 PSD_BLOCKED로 막히므로, Pi가 잡기(`8`)와 함께 `[PF0]`, 놓기(`7`)와 함께 `[PF1]`을 보낸다. 부팅 기본값은 켜짐. `q`로는 바뀌지 않는다.

PSD raw 임계값550을 유지한다. 속도모드는 몸체 전진 속도 (vL+vR)/2로 방향을 정한다(2026-10-14 변경): 10 mm/s 초과 전진이면 정면, 후진이면 뒤, 전진·후진하며 회전(곡선)하면 측면까지 검사한다. **제자리 회전(|v| ≤ 10 mm/s)은 PSD로 멈추지 않는다** — 지름 330 mm 원형 몸체는 제자리에서 돌아도 벽에 가까워지지 않고, 400 mm 칸에서 벽 30~50 mm 거리의 측면·후면 PSD가 616~886으로 임계를 넘어 회전 자체가 막혔기 때문이다. 이 거리의 벽은 라이다(최소 0.12 m)가 본다. **PSD 정지는 조건이 60 ms 이상 계속될 때만(2026-10-15 추가)**: 표본 하나의 잡음(중앙값보다 70~150 높게 튐)으로 큐브가 집게 날 사이에 들어오기 전에 서던 것을 막는다. 0.06 m/s에서 약 4 mm 늦게 선다. 목표각 회전 시험도 네 방향을 검사한다. `# ABORT PSD_BLOCKED`가 발생하면 실제 주변 물체와 센서값을 확인한다. STM은 정지만 담당하며, 우회 경로 계산과 재출발 판단은 Pi 담당이다.

## 10. 연동 완료 판단 순서

1. 버전·보정값 확인, 정지 상태20Hz CSV 수신.
2. 기존40cm·좌우90도 시험 재확인.
3. 새 속도 제어 `[V80,0]`을10초간 반복 전송하고 거리·횡변위·CSV를 비교.
4. 저속 좌/우 회전과 후진의 부호 확인.
5. 속도 명령 송신 중단 및 상위 속도 발행 중단 시 각각 정지 확인.
6. 실제 이동과odom의전진/회전 방향 비교, LiDAR TF확인.
7. 수동 저속 주행SLAM → 지도 확인 → 경로 추종·A*연동.

### 현재 검증 범위

오늘 기존 시험에서 거리·회전 보정값을 얻었다. 새 `BASE_NAV_V1`은 모의 Arduino 환경에서 상태 전이·정지·프로토콜 시험을 통과했지만 실제STM툴체인 컴파일·실기 업로드·ROS통합은 아직 검증 전이다.

직진 동기화 PID는P=.90,I=.40,D=0이다. **새 바퀴 속도 PI는 초기값이며 튜닝 완료 상태가 아니다.** 단위가 달라 직진 PID게인을 그대로 복사하지 않았다. SLAM·경로 추종 시험 전에 새 속도 추종 결과를 STM담당과Pi담당이 함께 확인한다.
